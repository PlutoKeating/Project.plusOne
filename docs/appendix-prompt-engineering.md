# 📎 附录：AI 辅助学习指南 & Prompt 工程手册

加一一路学过来，每章都在向 AI 提问。同一个问题，问法不同，得到的回答质量差别很大。这份附录整理了提问的方法和可直接套用的模板。

---

## 第 1 部分：Prompt 的五要素

| 要素 | 写什么 |
|------|--------|
| 角色 Role | AI 以什么身份回答 |
| 任务 Task | 要它做什么 |
| 背景 Context | 你的情况、已知条件、限制 |
| 输出 Output | 回答要包含哪些内容、多长 |
| 格式 Format | 用表格、列表、JSON 还是段落 |

对比：

```text
差：解释什么是 RAG

好：
角色：你是一个 AI 技术导师，面向零基础的初学者
任务：用不超过 200 字解释什么是 RAG
背景：读者已经了解基本的 LLM API 调用，但不知道 RAG
输出：先用一句话类比，再给一个技术定义，最后用 3 个要点说明为什么需要它
格式：Markdown 段落，不要用列表
```

## 第 2 部分：六个常用技巧

| 技巧 | 做法 | 什么时候用 |
|------|------|-----------|
| 角色指定 | 开头写"你是……" | 几乎所有场景 |
| 少样本示例 | 给几个"输入→输出"示例 | 要固定格式，或分类标准难用文字讲清 |
| 思维链 | 要求"分步展示推理过程" | 数学、多步推理、需要看到理由 |
| 结构化输出 | 规定 JSON 等固定结构 | 程序要解析回答，大多数 Agent 场景 |
| 任务分解 | 大任务拆成几个小提示词依次问 | 一次问不完，或步骤之间相对独立 |
| ReAct | 让模型交替"思考→行动→观察" | 构建 Agent |

### 角色指定

```text
普通：帮我写一段 Python 代码
角色化：你是一个有 10 年 Python 经验的资深工程师，注重代码可读性和类型安全。帮我写一段调用 OpenAI API 的代码。
```

### 少样本示例

```text
任务：将用户问题分类为"天气"/"计算"/"搜索"
输入：北京今天多少度？        输出：天气
输入：2500 * 12 等于多少？    输出：计算
输入：帮我查一下量子计算的最新进展  输出：搜索

现在分类：
输入：深圳明天会下雨吗？
输出：
```

### 思维链

```text
差：计算 25 * 4 + 100 / 2
好：计算 25 * 4 + 100 / 2，请分步展示计算过程
```

### 结构化输出

```text
请按以下 JSON 格式返回：
{
  "summary": "一句话总结",
  "key_points": ["要点1", "要点2", "要点3"],
  "sentiment": "positive/neutral/negative"
}
```

### 任务分解

```text
差：帮我分析这份数据，写报告，然后发邮件
好：
第一步：帮我总结这份数据的关键指标
第二步：基于总结写一份报告
第三步：把报告整理成邮件正文
```

### ReAct

```text
用户问题：北京的天气怎么样？
思考：用户想知道北京的天气，需要查天气工具。
行动：调用 get_weather(city="北京")
观察：返回"晴，25°C"
思考：信息够了。
回答：北京今天晴，25°C。
```

## 第 3 部分：各章 Prompt 模板

### 第 1 章：学 Python

```text
角色：你是一个擅长类比教学的编程导师
任务：用生活类比解释 [Python 概念：如字典、列表]
受众：零编程基础的学习者
要求：先用生活场景打比方，再给代码示例
输出格式：概念类比 → 代码示例 → 逐行解释
```

```text
角色：你是一个严格的 Python 代码审查员
任务：审查以下代码，指出风格问题和优化空间
我的代码：[贴代码]
审查重点：命名规范、异常处理、代码可读性
输出格式：按严重程度排序（严重/建议/小问题），每条附带修改建议
```

### 第 2 章：LLM API 调用

```text
角色：你是一个 API 调试专家
任务：帮我解决 API 调用错误
背景：我正在调用 [模型名] 的 API，语言是 [Python/JavaScript]
错误信息：[贴错误信息]
我已经尝试过：[列出尝试过的方案]
输出格式：最可能原因 → 验证方法 → 解决方案 → 预防措施
```

```text
角色：你是一个 AI 应用开发导师
任务：帮我理解 [参数名，如 temperature] 的作用
前提：我已经会基础 API 调用
要求：用可动手验证的方式解释，例如"把 temperature 设成 0 和 1 各试一次，观察区别"
```

### 第 3 章：RAG

```text
角色：你是一个 RAG 系统架构师
任务：帮我诊断 RAG 检索效果问题
我的场景：[文档类型和用户问题]
当前效果：[检索结果是否相关]
我的配置：[切块大小、嵌入模型、Top-K 值]
输出格式：可能原因排行 → 每个原因的验证方法 → 改进方案
```

```text
角色：你是一个 RAG 开发工程师
任务：把以下代码的向量库换成 [ChromaDB/Pinecone/Weaviate]
当前代码：[贴代码]
要求：功能不变，只替换向量库
```

### 第 4 章：Agent

```text
角色：你是一个 Agent 系统开发专家
任务：帮我设计工具集
场景：[应用场景]
要求：列出每个工具的名称、描述、参数（JSON Schema 格式）
输出格式：按优先级排序的工具列表，每个工具附选择理由和实现要点
```

### 第 5–6 章：Memory & Multi-Agent

```text
角色：你是一个 AI 系统架构师
任务：评审我的 [Memory / Multi-Agent] 设计方案
我的方案：[设计描述]
评审维度：可扩展性、错误处理、成本、复杂度
输出格式：优势 → 风险 → 改进建议
```

### 第 7 章：面试准备

```text
角色：你是一个资深 AI 应用开发面试官
任务：对我进行模拟面试
我的背景：[如 1 年 Python 经验，做过 1 个 RAG 项目]
面试方向：AI 应用开发 / Agent 开发
要求：先问 3 道基础题，再问 2 道深入题，最后给综合反馈
```

## 第 4 部分：常见错误与改法

| 错误 | 差的问法 | 改后的问法 |
|------|---------|-----------|
| 太模糊 | 写一段代码 | 用 Python 写一个函数，调用 OpenAI API 实现多轮对话，包含对话历史管理 |
| 不给角色 | 解释什么是 Agent | 你是一个 AI 技术布道师，用通俗的方式向非技术人员解释什么是 Agent |
| 不指定格式 | 对比 RAG 和微调的优缺点 | 用表格对比 RAG 和微调：适用场景、成本、知识更新速度、准确性 |
| 一次要太多 | 帮我做一个完整的电商客服 Agent | 分三次问：设计工具集 → 实现查询订单工具 → 实现退货流程 |
| 不给背景 | 代码报错了 | 运行以下代码时报错：[代码]。环境：Python 3.10，openai 1.0，Windows。错误信息：[贴错误] |

## 第 5 部分：用 AI 辅助学习

### 学习四步

```text
1. 预习：让 AI 用 100 字概括今天要学的概念
2. 阅读：读教程，理解核心内容
3. 实践：自己敲代码，跑通为止
4. 巩固：让 AI 出题测验，或审查你的代码
```

### 卡住时先检查

1. 把完整错误信息给 AI 了吗？
2. 把你的代码和期望结果给 AI 了吗？
3. 告诉 AI 你已经试过哪些办法了吗？
4. 把相关章节内容告诉 AI 了吗？

四项都做了还卡住，就先跳过，往后学，回头再看。

### 避免这些做法

- 只把 AI 当搜索引擎
- 遇到问题不想就直接问
- 复制 AI 的代码，不理解就运行
- 从不自己敲代码
- 收藏大量资源但从不看

## 第 6 部分：快速参考卡

| 场景 | Prompt 模板 |
|------|------------|
| 概念解释 | "你是一个导师，用 [类比] 解释 [概念]，面向零基础" |
| 写代码 | "角色：[角色]。任务：用 [语言] 实现 [功能]。约束：[限制条件]" |
| 调试错误 | "角色：调试专家。错误：[错误信息]。代码：[代码]。已尝试：[方案]" |
| 代码审查 | "审查以下代码，按严重程度排序给出优化建议：[代码]" |
| 设计系统 | "角色：架构师。场景：[描述]。要求：给出文字版架构图和核心模块说明" |
| 模拟面试 | "角色：面试官。岗位：[岗位]。要求：先问基础再深入，最后给反馈" |
| 学新概念 | "用 100 字概括 [概念]，再用 3 个要点说明它解决什么问题" |
| 出练习题 | "角色：导师。主题：[主题]。难度：从易到难。数量：5 题。附带答案" |

## 写在最后

好的提示词靠反复修改得来：

```text
写 Prompt → 看结果 → 找问题 → 改 Prompt → 再看结果 → ……
```

第一版不完美没关系，每次用 AI 都是一次练习。加一的座右铭：

> **"先跑通，再优化。先做成，再做好。"**
