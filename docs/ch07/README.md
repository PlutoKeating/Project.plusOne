### 项目 1：知识库问答助手（RAG）

上传文档，系统根据文档内容回答问题，并展示引用的原文片段。

```text
入库：文档(PDF/TXT) → 解析 → 切块 → Embedding → 向量库
问答：用户问题 → Embedding → 向量库检索 Top-K 片段 → 拼进提示词 → LLM 生成答案 → 前端显示答案 + 出处
```

| 模块 | 负责什么 |
|------|----------|
| 文档解析 | 把 PDF、TXT 转成纯文本 |
| 切块器 | 把长文本切成几百字的小段 |
| Embedding + 向量库（FAISS / ChromaDB） | 把每段文字转成向量存起来，按语义相似度查找 |
| 生成模块 | 把检索到的片段和问题一起交给 LLM |
| 前端（Streamlit / Gradio） | 上传文档、提问、显示答案和出处 |

加分项：支持 Word、Markdown 等更多格式；针对中文换用更合适的 Embedding 模型；标出答案来自哪个文档的哪一段。

### 项目 2：多工具智能助手（Tool Calling）

一个能搜索、计算、查天气、记备忘、管待办的助手。

```text
用户消息 → 记忆模块补上历史 → LLM 决定是否调工具
   ├─ 需要工具 → 工具注册表找到函数 → 执行 → 结果回传 LLM → 再判断
   └─ 不需要   → 直接回答 → 写入记忆
```

| 模块 | 负责什么 |
|------|----------|
| 工具注册表 | 保存每个工具的名称、描述、参数说明和执行函数 |
| Agent 循环 | 反复"让 LLM 决定 → 执行工具 → 回传结果"，直到得出答案 |
| 记忆模块 | 短期记忆保留最近几轮对话，长期记忆存摘要或可检索的历史 |
| 错误处理 | 工具失败时重试，超过最大步数就停止 |

加分项：用 MCP 协议接入工具；在界面上展示每一步工具调用；允许用户添加自己的 API 作为工具。

### 项目 3：业务场景综合助手

把 RAG、工具调用、记忆组合起来，三个方向任选一个：

| 方向 | 场景 | 主要模块 |
|------|------|----------|
| A. 运营提效 | 运营团队查数据、出报表、发邮件 | 数据库/API 查询工具、报表模板、邮件工具、定时任务 |
| B. 数据分析 | 上传 Excel/CSV，用自然语言提问 | 数据预览、自然语言转 SQL 或 Pandas 代码、图表生成、洞察报告 |
| C. 个人知识管理 | 收集零散信息，建个人知识库 | 网页抓取与摘要、标签归档、知识库问答、定期回顾 |

以方向 B 为例的数据流：

```text
上传 CSV → 预览表结构 → 用户提问 → LLM 生成查询代码 → 执行代码 → 得到数据 → 生成图表 + 文字结论
```

选题时挑一个你自己关心的领域（游戏、金融、教育、医疗都行）。调试到深夜时你会更愿意坚持，面试时面试官也能听出你对这个领域的兴趣。

## 项目目录结构

目录按模块划分，和上面的模块表一一对应：

```
my-ai-project/
├── .env                  # API Key 等密钥（不提交）
├── .env.example          # 环境变量模板（提交，不含真实密钥）
├── .gitignore            # Git 忽略规则
├── requirements.txt      # 依赖列表
├── README.md             # 项目介绍、运行方式、架构说明
├── src/
│   ├── config.py         # 从环境变量读取配置
│   ├── llm.py            # 封装 LLM 调用：错误处理、重试、Token 统计
│   ├── tools.py          # 工具注册表
│   ├── memory.py         # 短期 / 长期记忆
│   ├── agent.py          # Agent 循环
│   └── rag.py            # 加载、切块、Embedding、检索
├── data/                 # 文档和知识库数据，与代码分开
├── tests/                # 测试
├── ui/app.py             # Streamlit / Gradio 前端
└── notebooks/            # 实验用 Jupyter Notebook
```

安全提醒：`.env` 必须写进 `.gitignore`。API Key 一旦泄露到公开仓库，别人可能很快就用它产生大额账单。`.gitignore` 至少包含 `.env`、`.venv/`、`__pycache__/`、`*.pyc`、`.DS_Store`。

## 面试高频问题 TOP 20

### 基础概念类

| # | 问题 | 回答要点 |
|---|------|----------|
| Q1 | 什么是 RAG？为什么需要？ | 检索增强生成；生成前先查知识库；减少幻觉；适合私有或最新知识 |
| Q2 | RAG 和微调的区别？ | RAG 推理时查外部知识，不改参数，上手快；微调改参数，适合改变行为和风格 |
| Q3 | Agent 和 Chatbot 的区别？ | Agent = Chatbot + Tools + Loop；能感知、决策、执行 |
| Q4 | Function Calling 的原理？ | LLM 按工具描述输出 JSON（工具名 + 参数）；开发者执行后把结果交回 |
| Q5 | MCP 解决什么问题？ | Model Context Protocol，工具接入的开放标准；统一工具发现和调用接口 |
| Q6 | 什么是 Embedding？ | 文字转固定维度向量；语义近则距离近；用于语义搜索、聚类 |
| Q7 | 什么是 ReAct？ | Reasoning + Acting；思考 → 行动 → 观察 → 再思考 |
| Q8 | 什么是幻觉？如何缓解？ | 看似合理的错误内容；RAG 提供依据、Prompt 限定角色、调低 Temperature |

### 实践类

| # | 问题 | 回答要点 |
|---|------|----------|
| Q9 | 介绍一个你做过的 Agent 项目 | 场景 → 架构 → 技术选型 → 核心实现 → 遇到的问题 → 解决方法 |
| Q10 | 如何处理 Agent 的异常？ | 超时重试、工具调用异常捕获、最大步数限制、工具不可用时友好降级 |
| Q11 | 如何设计工具接口？ | 职责单一、名称和描述清楚、参数有类型、错误处理完善 |
| Q12 | Agent 陷入死循环怎么办？ | 最大迭代步数、检测连续重复输出、无工具可调时直接回答 |
| Q13 | 上下文窗口满了怎么办？ | 滑动窗口保留最近 N 轮、摘要压缩、按 Embedding 相关性保留重要内容 |
| Q14 | RAG 检索效果差怎么排查？ | 切块是否切断语义、Embedding 模型是否适合语言和领域、是否需要改写查询 |

### 设计类

| # | 问题 | 回答要点 |
|---|------|----------|
| Q15 | 设计一个客服 Agent | 需求分析 → 架构 → 工具 → 知识库 → 记忆策略 → 异常处理 |
| Q16 | 如何评估 Agent 系统？ | 任务完成率、平均轮数、工具调用准确率、用户满意度、端到端延迟、Token 消耗 |
| Q17 | 多 Agent 和单 Agent 怎么选？ | 是否需要不同角色、是否需要并行、单 Agent 上下文是否常不够用；满足 2 项以上再考虑多 Agent |
| Q18 | 如何保证 Agent 安全？ | 防 Prompt 注入、工具权限控制、敏感信息过滤、输出审核、高风险操作人工确认 |
| Q19 | 选哪个 Agent 框架？为什么？ | LangChain 生态丰富、Semantic Kernel 适合微软生态、CrewAI 和 AutoGen 适合多 Agent；给出自己的理由 |
| Q20 | 未来 1–2 年的方向？ | Agent 工程化（MCP 等标准）、多模态 Agent、垂直领域 Agent、端侧 Agent |
