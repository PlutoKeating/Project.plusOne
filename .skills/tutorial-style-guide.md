# Tutorial Style Guide — Skill

## 概述

本 skill 用于指导 AI 在为「加一的 Agent 成长之路」教程生成新页面时，维持原有的文本风格、叙事背景、知识点阐述逻辑与内容结构。

---

## 1. 叙事风格规范

### 1.1 主角设定

- **主角**：加一（plusOne）— 一个从零开始培养的 AI 助手
- **背景**：2018 年，PlutoKeating 决定打造全方位智能助手
- **寓意**：加一的每一步成长，对应开发者需要掌握的技能

### 1.2 语言风格

- **亲切拟人化**：将技术概念拟人化，如"加一需要一具身体"、"加一睁开双眼"
- **避免学术腔**：使用口语化表达，贴近日常对话
- **故事驱动**：每个章节以"加一的成长故事"开篇（2–4 句），引出技术主题
- **面向小白、一目了然**：删掉铺垫和重复；术语首次出现时给一句白话解释
- **只讲架构**：讲清"由哪几块组成、数据怎么流动、每块负责什么"，不展开代码细节

### 1.2.1 措辞禁令

不使用以下词句或句式：

- "底线是"、"深入探讨"、"促进"、"利用"、"值得注意的是"、"重要的是"、作强调用的"真正"
- "简而言之"、"总之"、"一句话总结"、"最简单的思维模型是"等结论性总结句
- 自问自答（"为什么？因为……"）、"这是错的。"式反转句
- "这不是关于 X，而是关于 Y"、"X，而不是 Y"、"X——而非 Y" 等对比框架（对比本身是知识点时用表格呈现）
- 生造的复合标签、带连字符的复合形容词、模糊限定语、陈腐过渡语（"让我们来看看"、"话不多说"）
- 说明"本节不会讲什么 / 什么保持不变"的句子

用平实的动词和介词直接陈述关系。

### 1.3 示例表达

| 技术概念 | 拟人化表达 |
|---------|-----------|
| Python 基础 | 加一的身体 |
| LLM API 调用 | 加一睁开双眼 |
| RAG 系统 | 加一学会读书 |
| Agent 循环 | 加一学会动手 |
| Tool/MCP/Memory | 加一的工具箱 |
| Multi-Agent | 加一的团队 |

## 2. 知识阐述逻辑

### 2.1 核心结构：Why → What → How

```
┌─────────────────────────────────────────────────┐
│  为什么需要？（Why）                              │
│  ├─ 解决什么问题？                               │
│  └─ 没有它会怎样？                               │
├─────────────────────────────────────────────────┤
│  是什么？（What）                                │
│  ├─ 核心概念定义                                 │
│  └─ 与已有知识的关联                             │
├─────────────────────────────────────────────────┤
│  怎么搭？（How）                                 │
│  ├─ 架构图 / 流程图 / 组件表                     │
│  └─ 必要时一段极短伪代码                         │
└─────────────────────────────────────────────────┘
```

### 2.2 章节结构模板

```markdown
# [emoji] 第 N 章：[标题]

## 故事：[加一的成长故事]

[用拟人化故事引出本章主题]

## 需要学到什么程度？

[明确学习目标，避免过度学习]

| 知识点 | 为什么需要 | 优先级 |
|--------|-----------|--------|
| xxx    | xxx       | ⭐⭐⭐  |

---

## [核心内容分区]

### 1. [子主题 1]

[组件表或流程图]

### 2. [子主题 2]

```text
# 仅在文字和图讲不清时，放一段不超过 15 行的伪代码
```

---

## 本章小结

[回顾关键知识点]

## 下一章预告

[为下一章做铺垫，保持故事连贯性]

## 3. 代码与伪代码规范

### 3.1 原则

- 优先用表格、```text 箭头图或 ```mermaid 图说明架构
- 只有流程讲不清时才放伪代码，每段不超过 15 行，每章不超过 2 段
- 不写 import、真实 SDK 调用、API 参数细节、完整安装命令
- 伪代码注释用中文，变量用有意义的英文名

### 3.2 伪代码示例

```text
循环 最多 N 步:
    回复 = LLM(对话历史, 工具列表)
    如果 回复 要调用工具:
        结果 = 执行工具(回复.工具名, 回复.参数)
        把 结果 加入 对话历史
    否则:
        返回 回复.文本
```

## 4. 附加页面创建流程

### 4.1 文件位置与命名

```
docs/chXX/extra-NN-<slug>.md
```

- `XX`：章节编号（01-07）
- `NN`：附加页面序号（01, 02, 03...）
- `<slug>`：简短的英文描述，使用连字符分隔

**示例**：
- `docs/ch01/extra-01-virtual-env.md`（第1章的虚拟环境附加阅读）
- `docs/ch03/extra-02-vector-database.md`（第3章的向量数据库附加阅读）

### 4.2 创建步骤

#### 步骤 1：创建新文件

```bash
# 复制模板
cp docs/chXX/extra-template.md docs/chXX/extra-NN-<slug>.md
```

#### 步骤 2：填写内容

按照模板结构填写，确保：
- 标题包含 `[emoji] 附加阅读：[标题]`
- 关联章节信息正确
- 内容风格与主章节一致

#### 步骤 3：更新 _sidebar.md 与 所属章节的 README.md

在 _sidebar.md 对应章节下添加链接：

```markdown
- [🧱 第1章：Python 快速起步](ch01/)
  - [附加阅读：虚拟环境详解](ch01/extra-01-virtual-env.md)
```

在 所属章节的 README.md 中添加链接：

```markdown
## 📖 附加阅读
- [虚拟环境详解](ch01/extra-01-virtual-env.md)

## 📚 参考资料
...（原有内容保持不变）
```

#### 步骤 4：Git 同步

```bash
git add docs/chXX/extra-NN-<slug>.md docs/_sidebar.md docs/chXX/README.md
git commit -m "docs(chXX): add extra reading - <slug>"
git push
```

### 4.3 Commit 消息规范

```
docs(chXX): add extra reading - <slug>
```

**示例**：
- `docs(ch01): add extra reading - virtual-env`
- `docs(ch03): add extra reading - vector-database`

## 5. 内容质量检查清单

在发布新页面前，检查以下内容：

- [ ] 叙事风格与原教程一致（拟人化、亲切）
- [ ] 知识阐述逻辑清晰（Why → What → How）
- [ ] 只讲架构，伪代码极短且必要
- [ ] 无 1.2.1 中的禁用词句
- [ ] 与主章节内容关联明确
- [ ] _sidebar.md 已更新
- [ ] Git commit 消息规范

## 7. 常见错误避免

| 错误类型 | 正确做法 |
|---------|---------|
| 使用学术腔 | 使用口语化、拟人化表达 |
| 缺少故事背景 | 以"加一的成长故事"开篇 |
| 贴大段代码 | 改成架构图、组件表或极短伪代码 |
| 啰嗦铺垫、结论性总结句 | 直接陈述事实和动作 |
| 知识点孤立 | 说明与主章节的关联 |
| 过度深入 | 保持"最小可行知识"原则 |
